## 🔍 Детальное обоснование для вопросов на интервью (проекты М)

### 1. `01_MCP_Сервер_Нефтегаз_RAG`
* **Вопрос интервьюера:** *«Какие документы загружены в векторную базу Qdrant? Есть ли там внутренняя документация Газпром нефти?»*
* **Ответ кандидата:** 
  > *«В базе находятся исключительно **официальные открытые стандарты**, опубликованные в свободном доступе: ГОСТ Р 53711-2009 (Правила разработки нефтяных месторождений), СТО Газпром по проектированию газопроводов и Федеральные нормы и правила Ростехнадзора (ФНП № 534 по предупреждению ГНВП). Внутренние ДСП-документы компании не использовались. Проект создавался как личный R&D для практического освоения новейшего стандарта Anthropic — Model Context Protocol (FastMCP) на Python 3.13, чтобы показать, как внешние LLM-агенты безопасно подключаются к векторным хранилищам через stdio и JSON-RPC»*.

### 2. `02_Дайджест_Рынка_Нефти_Brent`
* **Вопрос интервьюера:** *«Откуда вы берете биржевые котировки и аналитику? Это платные терминалы Bloomberg/Refinitiv?»*
* **Ответ кандидата:** 
  > *«Нет, проект полностью построен на открытых бесплатных источниках: котировки берутся из публичных API биржи ICE / Yahoo Finance, а новостной фон собирается через открытый RSS-поток Google News по отраслевым тегам. В коде также реализован аварийный стохастический генератор (геометрическое броуновское движение), который страхует систему от сбоев внешних API. Проект делался как личный пет-проект автоматизации: он рассчитывает скользящие средние (SMA-7, SMA-30), волатильность за 30 дней и 6 месяцев, строит графики на Matplotlib и формирует сценарный прогноз цен для аналитиков»*.

### 3. `03_Мультиагентная_Система_Judge`
* **Вопрос интервьюера:** *«Что проверяет этот мультиагентный конвейер? Это код реальных систем компании?»*
* **Ответ кандидата:** 
  > *«Это архитектурный прототип контура самокритики (Reflexion Loop). В качестве задач используются тестовые синтетические инженерные модули (например, расчет забойного давления и гидравлики скважины). Ключевая ценность проекта — реализация паттерна **Evaluator-Optimizer + Model Diversity + LLM-as-a-Judge** из методологии Anthropic 'Building Effective Agents': первый агент декомпозирует задачу, второй генерирует код, третий находит дефекты, а четвертый (независимая модель-судья) выносит строгий вердикт и отправляет на итеративную доработку. Это ровно та архитектура, которая необходима для ноды-критика в корпоративных аналитических системах»*.

### 4. `04_RAG_Бот_Нефтегаз_Документы`
* **Вопрос интервьюера:** *«Для чего разрабатывался RAG-бот и какие данные в него загружались?»*
* **Ответ кандидата:** 
  > *«Это личный прикладной проект, созданный в процессе обучения в СамГТУ (кафедра 'Цифровые технологии в нефтегазовой отрасли'). В бот загружались открытые учебные регламенты по предупреждению газонефтеводопроявлений (ГНВП). Главный инженерный акцент проекта — отработка защиты от галлюцинаций (Zero-Hallucination Prompting): бот отвечает строго по загруженным выдержкам, а при отсутствии информации честно сообщает об этом, что критически важно для промышленного сектора»*.
